产品部署手册

一、文档目的

本文档用于说明企业版产品的部署方式、部署前准备、基础环境要求、服务配置流程、常见部署问题和验收标准。售前、交付、运维和客户技术负责人可以根据本文档完成私有化部署方案评估和实施准备。

二、支持的部署方式

1. 标准服务器部署

企业版产品支持部署在客户自有服务器中。客户需要提供 Linux 或 Windows Server 环境，并提前准备数据库、应用运行目录、文件存储目录和网络访问端口。

适用场景：
- 客户要求数据保存在内部网络。
- 客户已有统一运维平台。
- 客户希望对服务器、数据库和日志进行自主管理。

2. 内网私有化部署

产品支持完全内网环境部署。内网部署时，系统不主动访问公网服务。大模型、文件存储、数据库和应用服务都需要部署在客户内网环境中。

适用场景：
- 金融、政企、医疗等对数据安全要求较高的客户。
- 客户禁止业务系统访问公网。
- 客户要求所有访问日志、问答记录和知识库文档保存在内部机房。

3. 混合部署

混合部署适合客户希望业务数据保存在内网，但允许调用外部大模型服务的场景。此时知识库文档、用户数据、问答记录仍保存在客户服务器中，AI 模型调用通过受控网关访问外部服务。

三、服务器环境要求

应用服务器建议配置：
- CPU：4 核及以上。
- 内存：8GB 及以上。
- 磁盘：100GB 及以上，需根据文档数量和日志量预留扩容空间。
- 操作系统：Linux CentOS、Ubuntu、Debian，或 Windows Server。
- 网络：应用端口、数据库端口、文件访问端口需要按客户安全策略开放。

数据库服务器建议配置：
- MySQL 8.0 或 PostgreSQL 15 及以上。
- 如果使用 PGVector，需要安装 PostgreSQL 和 pgvector 扩展。
- 数据库需要单独设置业务账号，不建议使用 root 或超级管理员账号连接业务系统。

四、基础组件说明

系统主要包含以下组件：

1. Web 前端

Web 前端负责用户登录、后台管理、知识库维护、文档上传和智能客服交互。前端构建后可以通过静态资源方式访问。

2. Spring Boot 后端

后端负责用户认证、业务接口、文件上传、文档管理、知识切片、向量检索和大模型调用。

3. 数据库

数据库保存用户、知识库、知识文档、知识片段、向量记录、问答记录和来源引用记录。

4. 文件目录

文件目录用于保存上传的企业文档。管理员上传产品手册、售后流程、公司制度等文件后，系统会保存文件访问地址，并在后续解析阶段读取文件内容。

5. 向量检索组件

PGVector 用于保存知识片段向量。用户提问时，系统会把问题转换成向量，再从 PGVector 中检索相似知识片段。

五、部署前准备

部署前需要确认以下信息：

- 客户服务器地址和登录方式。
- 数据库类型、地址、端口、账号和密码。
- 文件保存目录。
- 应用访问域名或 IP。
- 是否需要 HTTPS。
- 是否需要接入统一认证系统。
- 是否允许调用公网大模型服务。
- 是否使用本地大模型或私有模型服务。
- 文档上传大小限制。
- 日志保留周期。

六、应用配置说明

后端配置文件中需要配置数据库连接信息：

数据库地址示例：
jdbc:mysql://localhost:3306/ai_knowledge

文件访问地址示例：
http://localhost:9090

如果部署到服务器，需要将 localhost 改成服务器 IP 或域名。

七、部署流程

1. 初始化数据库

在数据库中创建业务库，并执行项目 SQL 脚本。执行完成后，应包含用户表、知识库表、知识文档表等基础表。

2. 上传后端应用

将后端项目打包后的 jar 文件上传到服务器，确认配置文件中的数据库地址、账号、密码和文件访问地址正确。

3. 启动后端服务

启动 Spring Boot 应用，观察控制台日志，确认服务端口正常监听，数据库连接成功。

4. 构建前端项目

在前端项目中配置后端接口地址，执行构建命令，生成静态资源。

5. 访问系统

通过浏览器访问系统登录页，使用管理员账号登录后台，检查用户管理、知识库管理、文档管理等页面是否能正常访问。

八、验收标准

部署完成后，需要完成以下验收：

- 管理员可以正常登录系统。
- 用户管理页面可以查询用户数据。
- 知识库管理页面可以创建、编辑和查询知识库。
- 知识文档管理页面可以上传文件，并保存文件地址。
- 文件下载地址可以正常访问。
- 后端日志没有数据库连接异常。
- 页面刷新后路由访问正常。

九、常见问题

1. 页面可以打开，但接口请求失败

需要检查前端配置的接口地址是否正确，后端服务是否启动，浏览器控制台是否存在跨域错误。

2. 文件上传成功，但无法下载

需要检查 fileBaseUrl 配置是否正确，服务器是否允许访问文件下载接口，文件是否真实保存到 files 目录。

3. 数据库连接失败

需要检查数据库地址、端口、账号、密码和数据库名称是否正确，同时确认服务器防火墙是否允许访问数据库端口。

4. PGVector 无法使用

需要确认 PostgreSQL 已安装 pgvector 扩展，并在数据库中执行扩展启用语句。向量检索功能依赖该扩展保存和查询向量数据。
